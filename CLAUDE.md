## Hard constraints

From `docs/spec.md` "Hard constraints". A PR that breaks one must fail CI.

1. **Deterministic.** Same inputs + same `RULES_VERSION` → same output. No randomness, no reading the clock; every rule takes an explicit `as_of`.
2. **No AI at runtime.** No LLM/ML-service calls, client or server, and no learned or statistical models in the code (owner decision, October 28, 2026: the October 11 exception for a bundled category model is revoked and the model removed). No model ever judges, guesses or decides anything about the person's money. One exception, owner decision October 28, 2026: on-device text recognition for receipt photos (Tesseract, fast-follow 6), which only reads letters from a photo the person chooses, runs only when they tap "Read text from photo", is served from the app's own files and never leaves the device; its suggestion is shown for review and fills nothing until "Use these". It is deterministic for a given device and pinned engine version (`ocr_engine_version` is stored with the text). `tools/check_ai_denylist.py` scans every `package.json`, `pnpm-lock.yaml`, `pyproject.toml`, `uv.lock`, `requirements*.txt` against `tools/denylist.txt` (glob patterns, npm and PyPI names) and has a `--self-test`. Claude Code is a build-time tool only.
3. **Read-only linking only, and only on Connected.** Owner decision, October 12, 2026: Phase 3 (Plaid, banks and cards) ships before go-live and is part of the launch gate. Data enters by manual entry, statement upload, receipt photo, or Connected's read-only linking; Free and Private never link. Never bank passwords, never money movement. Linking stays off unless `STACKD_PLAID_*` and `STACKD_LINK_TOKEN_KEY` are set; production needs Plaid's approval and the one-time legal review of the public wording.
4. **PWA first.** Installable, offline for viewing and logging. Never assume a native shell; Capacitor wraps the same build in Phase 2.
5. **Store-ready from day one.** In-app deletion in two taps, public web deletion page, full export, privacy and terms links.
6. **Plain language.** No jargon without a one-line explanation. Nothing is financial advice; education carries a disclaimer.

**Local-first.** Statements, receipt photos and transactions live only in IndexedDB on the device. The server gets only account/passkeys, plan, group **% progress**, a minimal alert schedule (date, type, generic label), and ciphertext backups. `tools/check_network_allowlist.py` fails on any URL literal under `services/` whose host is not in `tools/network_allowlist.txt` (supports `*.host`; a line ending `# net-allow: reason` is exempt). At runtime `services/api/app/security/outbound.py` refuses the same hosts; every outbound call goes through `outbound_client()`, and its packaged copy of the allowlist must equal the `tools/` one (tested).

## Rules conventions (`services/rules` and `packages/rules`)

- **Integer cents** everywhere (`*_cents`); percentages in basis points (`bps`, 10000 = 100%); APR in `apr_bps`. All rounding goes through `money.round_div` (half-even via `round(Fraction)`), nothing else rounds. Display formatting is the web app's job (`lib/format.ts`).
- **Dates** are ISO `YYYY-MM-DD` strings at the boundary, `datetime.date` inside, no times or zones; the caller passes the user's local date as `as_of`. Payday schedules are `{"kind": "every_n_days", "anchor", "n"}` or `{"kind": "monthly_days", "days": [...]}`.
- **Pure functions.** No I/O, no clock, no third-party runtime deps (keep it plain Python, no pandas, so both Pyodide and a TS port stay viable for 0.6).
- **Errors.** Bad input raises `RuleError(code)` with a stable snake_case code; nothing else.
- **Registry contract.** `registry.RULES["<module>.<rule>"](**input_json) -> output_json`, identical in Python (`stackd_rules/registry.py`) and TypeScript (`packages/rules/src/registry.ts`). The TS tests assert the key set equals the golden directories and that `RULES_VERSION` matches, so a rule on one side only fails CI.
- **Adding or changing a rule, in this order, in one PR:** formula in `docs/spec.md` → golden cases with hand-derived expected values → Python → TypeScript → `RULES_VERSION` bump (both `stackd_rules/__init__.py` + `pyproject.toml`, and `packages/rules/src/version.ts`) if any output changed.
- **Text and dates behave the same in both engines (invariant 10, October 27, 2026):** every string comparison in the TS port goes through `text.ts` `compareText` (code-point order, as Python compares str; never `localeCompare`, which follows the device's language, nor `<` on text, which compares UTF-16 units); whitespace is the one list `SPACE_CLASS` in `text.ts` and `stackd_rules/text.py` (JavaScript's `\s` spelled out: never Python's `\s` or `strip()`), through `collapseSpaces` / `trimSpaces`; character n-grams count code points (`Array.from`); calendar days go through `dates.ts` `utcMs` (`setUTCFullYear`), never `Date.UTC`, which reads years 0–99 as 1900–1999.
- **Engine boundaries (October 28, 2026; RULES_VERSION 0.32.0):** `money._int` / `assertInt` answer `too_large` past 2^53 − 1, and both registries check every output integer the same way (`money.check_output` / `checkOutput`); products into `roundDiv` or comparisons go through `money.mul` (BigInt) in the port; a date stepped past year 1 or 9999 is `invalid_date` (Python's OverflowError is mapped in the registry); in the port an array is never a record; a top-level optional argument that is `null` means its default in both, a nested field follows `dict.get`; `notify.decide` prefs are strict booleans; the shortfall alert key carries a 16-letter FNV-1a tag (`alerts.amount_tag`), never the amount. Python never uses `strftime` (glibc drops the zero pad before year 1000): `isoformat()`.
- **The TS port never touches floats for money:** `roundDiv` uses BigInt, `parseAmount` works on digit strings, dates are UTC day numbers. If Python can do something JS cannot mirror exactly, change Python (regexes are ASCII-only `[0-9]` for this reason).
- **Golden tests.** `tests/golden/<rule>/<case>.input.json` + `.expected.json`; a `RuleError` compares as `{"error": code}`. Expected values are derived by hand from the spec, never generated from the code under test. Meta tests fail if a registered rule has no cases or a case directory names no rule. The TS engine port runs the same files from `apps/web/tests/engine/`.
- **Versioning.** `RULES_VERSION` in `stackd_rules/__init__.py` must equal `pyproject.toml` version (tested). Bump it whenever any output can change for the same input. Stamp it on every computed result.
- Thresholds and ordering live in versioned config, not code: `stackd_rules/config/next_move.yaml` (edit, then `uv run python scripts/build_next_move.py`), `keywords.yaml` (edit, then `uv run python scripts/build_keywords.py`; rules take the table as input so they stay pure), and `services/api/app/rules_server/plans.yaml` (not yet). Formulas for every rule are in `docs/spec.md` "Calculation rules"; every value once marked "proposed" was signed off by the owner on October 27, 2026; a new threshold needs the owner's sign-off, never an invented one.

## Security conventions (`services/api`)

- Every route that touches a user-owned row goes through `app/security/authz.py`: `get_owned` for one row, `owned_by` for lists, never a bare `session.get`. Another user's row answers 404 `not_found`, not 403.
- Export, delete, email change, plan change and bank linking call `require_fresh_passkey(principal)` first (window `STACKD_STEP_UP_MAX_AGE_SECONDS`, 300).
- Abuse-prone routes declare `Depends(rate_limited("<scope>"))`; scopes and values live only in `rate_limit.LIMITS` (signed off October 27, 2026). The counter commits on its own, so a failed request still counts.
- Security-relevant events call `audit.record(session, actor_id=..., action=AuditAction.X, target="kind:id", ip=client_ip(request))`. New actions go in the enum. Never amounts, merchants or free text.
- Outbound HTTP only through `outbound_client()`. Adding a host means editing `tools/network_allowlist.txt` **and** copying it to `app/security/network_allowlist.txt`.
- Rows owned through a membership (groups) use `_active_member` in `routers/groups.py`: not a member is 404, exactly like someone else's row; owner-only actions on a group you are in are 403 `owner_only`.
- Push delivery goes through `services/push.send` only (pywebpush encodes, py_vapid signs, `outbound_client` sends); tests set `push.transport_override`. Never put a dollar amount, a merchant or an account in a push payload or an alert label.
- Deleting an account goes through `services/deletion.soft_delete` only (sessions, passkeys, codes, tombstone email, group ownership) and the purge through `purge_due`; nothing else touches `users.deleted_at`. The email tombstone keeps `users.email` unique and frees the address.
- Every new router adds a cross-user case to `tests/authz/` (pattern: `test_ownership.py::test_route_pattern_denies_cross_user`). `tests/security/test_route_guards.py` covers every new route automatically; a route that must work without a session goes in its `PUBLIC` set on purpose, and nothing cookie-authenticated ever goes under `/api/public/`.
- Settings have no default secrets. A new secret is added to `app/config.py`, `.env.example`, `docker-compose.yml`, `tests/_env.py`, and the secret store.
- The security owner (the Director) reviews any change to `app/security/`, `tools/denylist.txt`, `tools/network_allowlist.txt`, or `docs/security/`.
- Routers that need a signed-in user take `caller: Annotated[Caller, Depends(require_unlocked)]` (or `require_session` only for the sign-up steps before the first passkey, `require_step_up` for export, delete, email change, plan change, bank link, passkey/device removal). `caller.principal` feeds the authz helpers; `caller.user` and `caller.session` are loaded.
- **Link with your phone** (server, October 19, 2026; `routers/device_link.py`, `models/device_link.py`, migration 0026): `POST /api/auth/link/start` (public, rate scope `device_link_start` 3/hour/IP, HttpOnly `stackd_link` cookie scoped to `/api/auth/link`, only hashes stored), `GET /status` (public; the approving account's session is picked up once, unlocked), `POST /lookup` (unlocked; `same_network` from the /24 or /64 pseudonym), `/approve` (step-up; 409 `different_network` unless `confirm_different_network`), `/deny`; audit `device_link_approved` / `_denied`, alert `DEVICE_LINKED`, rows purged by `purge-expired`. The screens come next.
- Errors that need a person go through `services/ops_alerts.report(kind, where, exc)` (October 25, 2026): `ReportErrors` middleware for unhandled API errors, the `jobs-loop` for failed jobs, `purge_due` for a skipped account; it emails `STACKD_ADMIN_EMAILS` once per kind and place an hour with the exception's type and our line only, never its message or request data, and never raises. A new place that swallows an exception to keep going calls it. No third-party error service.
- Anything that changes sign-in state calls `security_alerts.send_alert(...)` and `audit.record(...)` together; alerts are email now, push joins in 1.13, and neither has an off switch.
- The only cross-origin callers are the website's two public deletion routes and `GET /api/public/plans/founding` (Founding places left: `{cap, left}`, counts only, cached a minute; owner decisions October 14 and 22, 2026: the first 250 only, checkout answers 409 `founding_sold_out` after that), through `security/cors.py` and `STACKD_SITE_ORIGIN`; never add the site origin to `STACKD_ORIGINS` (WebAuthn and `same_site_only`), and never put a cookie-authenticated route under `/api/public/`. Public routes answer the same way whether or not an account exists.
- Backups and household blobs are opaque bytes: routes decode base64url, cap the size (8 MB / 64 KB) and store; nothing parses, logs or indexes their contents. Household routes resolve the caller's active membership (`_my_household`: not a member is 404) and check the owner's `household` entitlement for invites and blob writes. The passkey PRF output must never reach the server: the options route only embeds the salt it was given.
- Plan gating on the server goes through `rules_server/entitlements.py` (`require_feature`, `check_limit`), never a literal limit in a router; the numbers live in `plans.yaml`. Webhooks live in `app/webhooks/` with no session and no CSRF guard, verify the signature on the raw body before parsing, record each event id (`billing_events`) so a redelivery changes nothing, and audit the outcome as `PLAN_CHANGED` without amounts. Stripe is reached only as plain REST through `outbound_client` (no SDK, no extra HTTP stack).
- Tests drive the real endpoints with `tests/auth_flow.py` (`new_client`, `sign_up`, `assert_passkey`) and the software authenticator in `tests/webauthn_fake.py`; each client gets its own `X-Forwarded-For`, so per-IP limits behave as in production.
- New settings have no default secrets. WebAuthn needs `STACKD_RP_ID` (the app's domain; `localhost` in dev, never an IP) and `STACKD_ORIGINS`. Production refuses dev values (`cookie_secure`, `email_backend=smtp`, https origins).

## Architecture (target)

TypeScript PWA (React + Vite + `vite-plugin-pwa`, Dexie for IndexedDB) → thin Python API (FastAPI + PostgreSQL + S3-compatible storage for ciphertext only; sync SQLAlchemy sessions, CHECK constraints instead of Postgres enums, readiness answers one word per check and logs the rest). Money math runs **on the device** in a Web Worker via `@stackd/rules`, the TypeScript port (ADR 0001; Pyodide was measured at 5 MB and 1.4 s start-up versus 2 KB and 60 ms). `apps/web/src/engine/` (chunk 1.3) is only the worker wiring around `@stackd/rules/worker`. Static website in Astro. Auth: email OTP + mandatory WebAuthn passkey, no passwords. Billing: Stripe Checkout/Portal on web. Push: Web Push (VAPID). Monorepo: pnpm workspaces + Turborepo (`apps/*`, `packages/*`), uv per `services/*`. Biome for JS/TS/JSON, ruff for Python. Turborepo's auto-generated `AGENTS.md` is disabled via `agentGuidance: false`; this file is the guidance.

Theme system: one token set drives CSS custom properties. Six looks (owner decision, October 12, 2026): the PWA offers Modern, Minimal, Retro 80s, Pastel, Anime and Illustrative; the native apps offer Modern, Pastel and Anime (`NATIVE_LOOKS` in `@stackd/tokens`, `looksFor(native)` in ThemeProvider). Both write `users.look` from Settings → App look (`features/settings/LookPicker`, one tile per look painted by `data-look` on the tile); a look the platform doesn't offer shows Modern there and is not overwritten. Fonts per look are dynamic imports in `app/lookFonts.ts`, kept out of the precache and cached on first use by `sw.ts` (`look-fonts-v1`). `Illustration` in `@stackd/ui` draws hand-made spot illustrations (ink + offset wash, `sk-decor`) in empty states; look flourishes (Illustrative paper grain, Retro grid, Anime halftone) live in `ui.css` and are decoration only. In a native app (chunk 2.2) `ThemeProvider` holds the look: `localStorage` `stackd.look` for the first paint, then the session's `user.look` adopted by `LookSync` (a repeat of the last adopted value is ignored so a stale read never undoes a switch), `setLook` applies at once, `app/lookFonts.ts` dynamically imports the look's `@fontsource/*` latin files (Sora, Plus Jakarta Sans, Dela Gothic One, M PLUS Rounded 1c, DotGothic16), and `SettingsScreen` saves the pick to the account. `vite.config.ts` keeps those font files out of the service-worker precache. Same layout, same wording, locked semantic colors in every look; no per-look component forks. CSS: `@stackd/tokens` emits `--c-*` color variables plus `--radius-card`, `--border-card`, `--shadow-card`, `--radius-toggle`, `--font-*` for `:root` (Modern light default), `[data-look][data-mode]` and a `prefers-color-scheme` fallback for "system"; the app sets both attributes on `<html>` before first paint. WCAG AA contrast is checked in CI over 90 text/surface pairs across all 6 look × mode combinations.

Navigation: five tabs, **Home · Budget · Goals · Insights · Me** (Insights replaced Learn, owner decision October 18, 2026), plus a global + button. Viewport ≥ 900px gets the side rail (and two panes where a screen has them); below that the bottom tab bar. The `--c-*` blocks for a look match with or without `data-mode`, so "System" mode paints every look (a bug before October 12, 2026: it fell back to Modern in light).

Full target tree with every file is in `docs/spec.md` "Repository structure & delivery phases". Domains: site at `[domain]`, app at `app.[domain]` (separate service-worker scope).
